# Voxel Space Invaders

A new, standalone Voxel One browser game. Open `games/space-invaders/index.html` through an HTTP server. The website builder adds a Play link to the landing page. No account, external assets, package downloads, or game server are needed.

Three voxel alien models and a voxel player spaceship are drawn as shaded cube cells. Play includes a 45-alien fleet, boundary reversal and descent, faster movement as aliens die, bottom-row enemy fire, destructible shields, a bonus saucer, score, three lives, brief respawn immunity, harder waves, game over, and restart. An invasion ends the game. The saucer awards 100 points.

Use Left/Right or A/D to move, Space to fire, P or Escape to pause. iPhone/iPad browser controls support holding movement and Fire together with separate fingers. Pointer release/cancel clears held input. Losing focus or hiding the tab pauses the game. Resume clears held controls. Portrait and landscape layouts respect safe areas. This is a web game, not a native iOS package; no Java/GLFW client runs on iOS.

Run rules checks with `node --test games/space-invaders/game.test.mjs`. Build with `python3 deploy/build_site.py`. Serve `website/dist` on port 8766, then run `deploy/test_space_invaders.cjs` with Playwright and its WebKit browser installed. `PLAYWRIGHT_MODULE` selects the installed module. Use a writable `TMPDIR` under the worktree for sandboxed browser profiles. Browser tests use synthetic profiles and no account data. Mobile WebKit emulation does not validate physical iOS devices.

The space scene fills the viewport in portrait, landscape, and desktop layouts. Score, lives, wave, pause, and touch buttons overlay the scene. Stars, layered nebula clouds, distant block worlds, and a receding voxel deck surround the shaded cube fleet. Combat positions span the available screen while cube faces keep their square proportions. Resize keeps the current game state. No external art assets are loaded.

Run `deploy/test_space_invaders_layout.cjs` against the same local server to check start, playing, paused, and game-over states at 568×320, 667×375, 844×390, and 390×844. It checks full viewport coverage, HUD/control bounds and reachability, overlay bounds, touch target size, and touch navigation through each state.

Collision bounds use the same voxel front, top, and side extents as the renderer, converted through the current viewport scale. Alien, ship, saucer, shield, and swept projectile bounds follow square sprites rather than stretched center spacing. Run `deploy/test_space_invaders_collisions.cjs` against the same server for landscape and portrait hit/miss checks.

Levels now alternate perspectives: level 1 uses classic Space Invaders; level 2 puts the camera inside the spaceship. Odd levels use the external ship view and even levels use the cockpit, with fighter combat on every level from level 2 onward. From level 2, arrows or WASD fly in two axes with acceleration and drift. Touch Up/Down adds vertical flight. Independent voxel jets weave and swoop toward the player, fire aimed shots, and can damage the ship on contact. Shields and formation descent stay in level 1. Fire launches from the current ship position; the cockpit camera follows its horizontal and vertical movement. Touch controls work the same way. The windshield rim, instruments and projected fleet replace the external player ship. Score and remaining lives carry across levels; restart returns to level 1.

Run `PLAYWRIGHT_BROWSERS_PATH=/tmp/voxel-web-qa/browsers TMPDIR="$PWD/.tmp/browser" node deploy/test_space_invaders_fighters.cjs` with the source checkout served at `http://127.0.0.1:8767`. This tests real firing for the level 1-to-2 transition with a synthetic final-alien setup, independent enemy paths, two-axis keyboard flight/fire, pause, death/restart, touch vertical flight/cancel, boundary clamps and level 3 fighter carryover. Captures and the report go in `dashboard/evidence/`.

Clearing level 2 starts a 12-second cockpit descent: a lit spherical planet grows ahead, the camera follows its curved horizon through spatial cloud layers, and the shared voxel landing region rises into an impact. Combat freezes through descent, blackout and awakening. Pause and focus loss freeze the story; restart clears it. Score and lives carry into level 3. Run `deploy/test_space_invaders_entry.cjs` against a source HTTP server on port 8779 to verify all phases, pause, level 3 flight/fire and restart in desktop, portrait and landscape WebKit.

Orbital descent uses a frozen planet profile, a 12-second camera path and a shared landing anchor. Canvas is the default reduced view; WebGL2 remains an opt-in preview. Missing Worker frames retain a prepared parent image. Regional samples, spatial atmosphere grids and image composition run in small preparation slices with a 2 ms scheduling budget; one generator step can exceed that budget. The frame callback does not generate terrain or trace a cold parent height field. Resize scales the retained image until a matching view is ready. Restart cancels both Worker jobs and sliced jobs, including level 2 prewarming.

Low uses a 33×33 regional field and a local landing patch, with at most 640 terrain faces. The distant world buffer is capped at 640 pixels wide and 480 high; the close Low buffer is capped at 320×240. HUD and controls keep their own crisp viewport resolution. The initial orbital image is a simpler sphere/limb sample of the same profile; prepared spatial scattering and cloud views replace it. The external fighter camera draws the bounded local mesh while its prepared backdrop catches up. Software browser timings and preparation latency are reported separately. Physical Safari iPhone and named desktop GPU checks remain a follow-up; they have not passed.

The Canvas parent uses precomputed surface fields and a spatial atmosphere grid. Cached world views interpolate between fixed camera poses; missing views keep the last prepared surface while bounded jobs catch up. The Worker reuses atmosphere grids and solar tables instead of integrating each body pixel, and orbital shading skips unused local slope queries. Message tasks yield between 2 ms slices without nested timer delays. The upper camera aims along the curved surface before returning to the same landing anchor. Close rays retain their bounded terrain search; orbital rays use one field sample and an analytic radius correction. This reduced path can blur enlarged detail and delay refinements; WebGL2 remains opt-in until compatibility and device performance gates pass.

Far views use macro material colours. Regional and landing-patch colours fade in below 6 km and reach full detail at 1.5 km; this changes colour sampling, not surface height. Regional samples interpolate between fixed seeded nodes. Cloud breaks use smooth seeded noise shared with GLSL. Stars account for cloud attenuation and total sky brightness.
