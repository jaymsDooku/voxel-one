# Persistent edit-history roots

`WorldVoxels.History.copyOf` now captures two immutable insertion-ordered index roots rather than cloning both complete maps. The source history still rotates its cell-index ownership token at every copy. Later source and snapshot edits clone shared mutable per-cell key sets separately. The generic index requires this external value protection; an immutable index alone does not freeze its values.

The key index uses the existing immutable chunk hash trie as an in-process integer-hash adapter. Exact string keys with the same full hash use balanced AVL buckets. Replay order uses a separate immutable AVL tree keyed by monotonic insertion ordinals. Replacing an existing key retains its position; removing and reinserting moves it to the end. Clear and copies do not alter retained roots. A copy retains both roots, size and next ordinal. Updates prepare both replacement roots before assigning either. Ordinals and tree nodes are never serialized. Overflow rejects before mutation.

Entry sets and entries remain read-only. Iterators detect changes to their own map; a copied history's edits do not invalidate a source iterator. History cursors retain their separate revision checks. Existing cell replay canonicalization, validation, world/package/save formats, model limits and admission caps remain unchanged. The diagnostic invariant walk is test-only and never runs on a live lookup or commit.

Offline structure staging now makes one owner call to capture history roots and one to recheck identity/revision after worker preparation. It no longer copies the whole history through repeated owner batches. Worker cell preparation, cancellation, progress and save staging remain detached. The final commit identity/revision fence remains mandatory. Legacy custom map histories retain their existing path.

Server structure staging captures history roots under its authority lock, then edits and writes the private candidate on the worker. The final history identity/revision fence still rejects stale candidates before save/world publication. Removing the old private cursor-copy routine is an intended replacement of that staging implementation. It grants no new mutation authority. Other current world edits may cause a retry; no concurrent edit is overwritten by an unchecked history swap.
