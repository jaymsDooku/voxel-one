# Owner-side region read fences

`RegionReadViewPrototype` is a private integration step, not a live game backend or placement authority. It exposes separate pending, ready and failed states. A pending or failed future never means empty terrain. A ready list preserves explicit known-absent source cells. At most 1,024 positions are captured.

Capture and every poll belong to the same owner thread under its world mutation lock. The view binds the world object, a non-null root publication epoch, model-library identity/revision and translated destination chunk stamps. Completion does not bypass these checks: every poll revalidates them before exposing data. Unrelated chunk edits remain valid. Changed affected geometry or terrain stamps, world/root/model changes, cancellation and read failures reject. Failure is sticky, so restoring an old identity cannot revive a stale view. Wrong result count or source positions also reject.

The caller must provide a new epoch on every root publication, including swapping back to an old root. This helper cannot observe root assignments automatically. A previously returned ready value is immutable data, not permission to mutate later. Any live consumer must revalidate under the authority lock immediately before publication. The trusted disk index/cache supplies validated frozen geometry; this view does not replace package/dependency validation, collision checks, atomic undo/save publication or failure rollback. Callers must bound live views and release stale references. No total memory or owner-thread timing guarantee is claimed.
