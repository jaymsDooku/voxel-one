# Stress Test Grid save

Start an offline city, then open Controls → City saves. Select **Stress Test Grid** and click **Load selected**. The game creates this independent save once. It does not replace an existing save with that name or alter Original city.

The layout contains 1,000,000 buildable plots in a 1000 × 1000 grid. Each plot is 16 × 16 blocks. Three-block-wide paved roads provide two lanes with a painted divider between every row and column, plus the outside perimeter. The total footprint is 19,003 × 19,003 blocks.

The centered residential area has 400,000 plots. The surrounding commercial, industrial and agricultural rings have 200,000 plots each. Exact percentages require splitting the boundary square layers. The split follows fourfold rotational symmetry, so the layout stays centered.

Click the colored map to visit a part of the grid. The map samples the full layout; nearby boundaries show individual plots. The last pixel on the lower-right map edge visits plot #1,000,000. Use the usual camera controls and F6 to change views. Save current and Save a copy preserve the complete layout and simulation clock.

To populate an existing benchmark, load **Stress Test Grid**, open Controls → City saves, and click **Develop stress save**. Click **Save current** to keep the result. This explicit benchmark action targets 192 houses, 80 commercial businesses, 80 industrial buildings, 48 crop farms (96 fields), and 128 detailed citizens. It creates real voxel buildings, privately owned properties, business operators, and resident housing contracts. The 128-citizen and 512-building save limits remain unchanged. These are synthetic benchmark assets and residents; the action does not pretend they were earned through normal construction. It preserves existing buildings, pending projects and player blocks, skips occupied sites, and fills only missing target counts. Repeating it does not duplicate the populated city. Crowded or edited sites and the building limit can reduce the additions. It is available only while the named stress save is loaded and never runs automatically on reload. Original city is unchanged.

This is a development-capable city benchmark. Normal founding households and horses start when the grid first loads. Demand, paid land purchases, material reservation, workers and completed buildings run through the usual simulator. The city starts without completed buildings; it does not seed one million citizens or one million buildings. The usual simulator population and project limits still apply. A finite initial stock lets development start without nearby forests: each property developer receives eight recipe sets each for residential, commercial and industrial buildings; each farming company receives two farm recipe sets. That stock is owned, reserved, consumed and saved through the normal economy. Loading developed state does not refill it. The prebuilt roads and zoning keep their requested layout. Inspect projects, citizens and buildings as usual; buildings can be demolished and the mayor dashboard remains available.

Plot geometry and road terrain are generated from a compact saved descriptor. Every plot has its own stable ID and polygon. Construction visits at most 64 candidate plots per demanded type in each pass, advancing through the full concentric rank range rather than scanning one million polygons. Completed and pending projects, residents, properties and supplies save alongside the compact descriptor. The engine loads nearby terrain and draws nearby zone boundaries rather than allocating all road voxels or drawing all polygons each frame. Long road routes use grid intersections rather than a search over the entire city area.

Stress saves use city format 15. Ordinary saves retain format 14. Parcel-enabled cities use format 16. Wire protocol 27 carries format 16 snapshots, including stress grids. Older city save formats still load through their existing readers.
