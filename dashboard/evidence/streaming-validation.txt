Sandbox streaming validation — Linux software renderer

The normal render loop no longer generates full terrain columns. One bounded
worker builds detached chunks with private terrain caches. The owner replays
current edits and attaches individual chunks under a cooperative deadline.
Existing DetailedMeshScheduler handles immutable snapshots and sliced uploads.
Measured sky expansion moved to the same bounded preparation lane; cached local
sky dependencies avoid unrelated GI rebakes. Lighting replacements upload in
bounded rows/bytes while existing resources remain active. No graphics defaults,
resolution defaults, draw distance, horizon coverage or generator version changed.

Environment: Linux amd64, 4 logical processors, Oracle Java 21.0.5, 1536 MiB maximum
heap, Mesa 22.3.6 OpenGL 3.3 llvmpipe LLVM 15.0.6. Requested Balanced 640x480 fell back
through existing display initialization to actual 1280x720 in every trial. Seed
748291, detailed distance 112, horizon 2048, scale 1, dynamic resolution off. Source
and jar hashes are in streaming-source-manifest.json. Software rendering is not
physical Windows GPU qualification.
